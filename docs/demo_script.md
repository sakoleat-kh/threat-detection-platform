# Threat Detection Platform — Demo Script

## 0:00–0:30 — Introduction

Hello, this is my Threat Detection Platform.

The platform is designed to ingest security logs, normalize the events, detect suspicious activity using predefined detection rules, map detected activity to MITRE ATT&CK techniques, store alerts in SQLite, and expose the results through a FastAPI REST API and web dashboard.

The goal is to demonstrate an end-to-end threat detection workflow rather than just a standalone detection rule.

---

## 0:30–1:00 — Architecture

The platform follows a layered detection pipeline.

Authentication logs and Apache access logs enter through the ingestion layer.

The appropriate parsers convert the raw log records into normalized security events.

Those events are passed to the detection engine, which evaluates them against the detection rules.

When a rule matches, the platform creates an alert and associates it with a MITRE ATT&CK technique and tactic.

The alert is then persisted in the SQLite database and exposed through the FastAPI API.

Finally, the web dashboard retrieves the data and visualizes the detection results.

---

## 1:00–1:40 — FastAPI and Swagger

Open the Swagger UI.

The API provides health checking, alert retrieval, alert filtering, statistics, and log ingestion endpoints.

The `/ingest/` endpoint accepts authentication and Apache access log files.

The `/alerts/` endpoint provides access to generated alerts, including filtering and pagination.

The `/stats/` endpoint provides aggregated statistics by rule, MITRE technique, and tactic.

This provides a programmatic interface to the detection platform in addition to the web dashboard.

---

## 1:40–2:30 — Dashboard

Open the dashboard.

At the top are the current top detection rule, MITRE technique, and MITRE tactic based on the stored alerts.

The rule chart shows the distribution of alerts across detection rules.

The MITRE tactic chart shows how the detected activity is distributed across ATT&CK tactics.

The recent alerts table provides the individual detection results, including severity, rule, MITRE technique, tactic, source, and user information.

The dashboard also provides filters for investigating alerts by rule, tactic, and date range.

This allows the analyst to move from an overall detection summary to individual alerts.

---

## 2:30–3:20 — Alert Investigation

Open the SQL injection alert.

This alert was generated by the SQL injection detection rule.

The alert has HIGH severity and is mapped to MITRE ATT&CK technique T1190, Exploit Public-Facing Application, under the Initial Access tactic.

The alert also preserves relevant event information.

In this example, the request targeted the `/search` path and contained a SQL injection pattern in the query string.

This demonstrates how the platform connects a raw security event to a detection rule, severity, and MITRE ATT&CK context.

---

## 3:20–4:00 — Detection and Ingestion

Return to the ingestion workflow.

The platform supports both authentication logs and Apache access logs.

During ingestion, the raw records are parsed and normalized before being evaluated by the detection engine.

The detection engine contains eight detection rules covering authentication and web activity, including brute force, excessive sudo activity, account creation, directory scanning, SQL injection, XSS attempts, and suspicious user agents.

When a rule matches, an alert is created, mapped to MITRE ATT&CK, and stored in the database.

---

## 4:00–4:20 — Closing

To summarize, the platform provides an end-to-end threat detection workflow:

log ingestion, parsing and normalization, rule-based detection, MITRE ATT&CK mapping, alert persistence, REST API access, and dashboard visualization.

The application is containerized with Docker and can be started as a reproducible deployment.
