# Performance Notes

## Day 62 Performance Evaluation

The ingestion pipeline was evaluated using synthetic log files generated by repeating the existing sample logs 26 times.

### Test Dataset

| Source | Input Lines |
|--------|-------------|
| Authentication log | 5,174 |
| Access log | 5,174 |

The full CLI ingestion tool was run against both files together.

### Results

| Stage | Runtime |
|-------|---------|
| Parse + normalize | 0.3309 seconds |
| Detection + MITRE | 0.1728 seconds |
| Database persistence | 0.0250 seconds |
| Total runtime | 0.5288 seconds |

### Processing Results

- Authentication events processed: 5,174
- Access events processed: 5,149
- Total events processed: 10,323
- Alerts generated: 2
- Alerts saved to database: 2

### Performance Analysis

The complete ingestion run processed more than 10,000 successfully parsed events in 0.5288 seconds.

Parse and normalization was the largest measured stage at 0.3309 seconds.

Detection and MITRE enrichment took 0.1728 seconds, while database persistence took 0.0250 seconds.

Based on this benchmark, parsing and normalization is the clearest current performance bottleneck. It accounts for the largest portion of the measured runtime and should be considered a future optimization target if the system needs to process substantially larger log volumes.

Database persistence was the smallest measured stage in this test.

### Limitations

This benchmark was performed using synthetic data created by repeating the existing sample logs. Therefore, the results represent the performance of the current implementation under this controlled workload and should not be treated as a production-scale benchmark.

Hardware, operating-system load, Python version, SQLite configuration, and other environmental factors can also affect the measured runtime.

Future performance work could include testing with substantially larger datasets and profiling the parsing and normalization stages to identify specific operations that consume the most time.
