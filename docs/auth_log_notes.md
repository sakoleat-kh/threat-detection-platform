# Authentication Log Notes

This document contains notes from manually reviewing Linux auth.log entries.
The purpose of this exercise is to understand the structure of authentication logs before writing code to parse or detect suspicious activity.

## Syslog Structure

Month | Day | Time | Host | Process | Message

Example:
Aug 6 09:15:22 ubuntu sshd[2543]: Failed password for invalid user admin from 192.168.1.15 port 51234 ssh2

Field Explanation

| Field | Description |
| Month | Month the event occurred (e.g., Aug) |
| Day | Day of the month |
| Time | Time the event occurred (HH:MM) |
| Host | Hostname of the Lixun machine | 
| Process | Program that generated the log (often includes a Process ID) |
| Message | Description of the event |

---

## Processes Found

During manual inspection, the following authentication-related processes may appear:
| Process | Purpose |
| sshd | SSH server handling remote logins |
| sudo | Records privilege escalation using sudo |
| CRON | Scheduled tasks executed automatically | 
| su | User switching (su) |
| systemd-logind | User login/session management |
| polkitd | Authorization service |
| login | Console login process |
| passwd | Password change events |

## SSH Failed Password Examples

Example 1 
Aug 6 09:15:22 ubuntu sshd[2543]: Failed password for invalid user admin from 192.168.1.15 port 51234 ssh2

Example 2
Aug 6 09:16:40 ubuntu sshd[2558]: Failed password for root from 192.168.1.20 port 40221 ssh2

Example 3
Aug 6 09:17:03 ubuntu sshd[2561]: Failed password for sakol from 192.168.1.25 port 40355 ssh2

Observation:
- Authentication failed.
- Source IP is recorded.
- Username is recorded.
- Useful for brute-force detection.

## SSH Accepted Password Example

Example 1
Aug 6 09:20:11 ubuntu sshd[2600]: Accepted password for sakol from 192.168.1.25 port 40355 ssh2

Example 2
Aug 6 10:04:42 ubuntu sshd[2534]: Accepted password for user from 192.168.1.30 port 42018 ssh2

Example 3
Aug 6 10:30:18 ubuntu sshd[2700]: Accepted password for ubuntu from 192.168.1.40 port 50022 ssh2

Observation:
- Login was successful
- Username and source IP are recorded.
- Indicates a legitimate authentication event.

## Invalid User Examples

Example 1
Aug 6 09:15:22 ubuntu sshd[2543]: Failed password for invalid user admin from 192.168.1.15 port 51234 ssh2

Example 2
Aug 6 09:18:05 ubuntu sshd[2580]: Invalid user test from 192.168.1.33 port 51002

Example 3
Aug 6 09:22:40 ubuntu sshd[2610]: Failed password for invalid user oracle from 192.168.1.18 port 49881 ssh2

Observation:
- The username does not exist on the system.
- Often associated with automated scanning or brute-force attacks.

## Notes from First 50 Lines

- Most authentication events were generated by the sshd process.
- Authentication logs consistently follow the syslog format.
- SSH events clearly distinguish successful and failed logins.
- Invalied user events reveal usernaames attachers are trying to guess.
- Successful logins use the phrase Accepted password.
- Failed logins use the phrase Failed password.
- sudo events record privilege escalation after a user authenticates.
- CRON events are routine scheduled jobs and are usually expected.
- Process IDs (for example, sshd[2543]) help distinguish different instances of the same service.
