# 1. Introduction

## 1.1 Problem Statement

Organizations generate large volumes of security-related log data from systems, authentication services, and web applications. These logs can contain valuable evidence of suspicious activity, but manually reviewing them is time-consuming and makes it difficult to identify recurring attack patterns consistently.

A security monitoring system therefore needs a way to process log data, identify potentially suspicious behavior, and present meaningful security alerts to an analyst. This project addresses this problem by developing a lightweight Threat Detection Platform that processes authentication and web access logs and applies predefined detection rules to identify selected security threats.

The platform transforms source-specific log entries into a normalized event format, evaluates the normalized events using a detection engine, generates alerts when detection conditions are met, maps detected activity to relevant MITRE ATT&CK techniques, and stores the resulting alerts for further analysis.

## 1.2 Motivation

The motivation for this project is to understand and demonstrate the core concepts involved in building a security threat detection pipeline.

Rather than relying only on individual log-parsing scripts, the project brings several security monitoring concepts together into one system. These include log parsing, event normalization, rule-based detection, alert generation, MITRE ATT&CK mapping, persistent storage, API development, and dashboard-based visualization.

This project also provides an opportunity to explore how a detection system can be structured into separate components so that parsing, normalization, detection, storage, and presentation responsibilities remain clearly separated.

## 1.3 Project Scope

The project focuses on building a prototype threat detection platform capable of processing selected Linux authentication logs and Apache access logs.

The main scope of the system includes:

- Parsing Linux authentication log entries.
- Parsing Apache-style web access log entries.
- Normalizing parsed events into a common event structure.
- Applying multiple rule-based detection mechanisms to normalized events.
- Detecting selected suspicious behaviors, including excessive sudo activity, SSH brute-force behavior, suspicious user agents, SQL injection attempts, XSS attempts, directory scanning, suspicious new-user creation, and successful authentication following failures.
- Generating structured security alerts when detection rules are triggered.
- Mapping detected alerts to MITRE ATT&CK techniques and tactics.
- Persisting alerts in a SQLite database.
- Providing REST API endpoints for alert retrieval, filtering, statistics, and log ingestion.
- Providing a web-based dashboard for viewing alerts and detection statistics.
- Running the application in a Docker container with persistent database storage.

## 1.4 Project Boundaries

This project is intentionally designed as a focused prototype rather than a complete enterprise security monitoring platform.

The following boundaries apply:

- The system focuses on the supported authentication and Apache access log formats rather than arbitrary log sources.
- Detection is based on predefined, rule-based detection logic rather than machine-learning-based anomaly detection.
- The platform processes supplied log files through its ingestion interface; it is not designed as a complete real-time enterprise log collection infrastructure.
- SQLite is used as the persistent database for this project.
- The dashboard provides visualization and investigation capabilities for the alerts generated by the platform, but it is not intended to replace a full enterprise SIEM or SOC platform.
- MITRE ATT&CK mapping is provided for the detection rules implemented in the project and does not represent complete ATT&CK coverage.
- The project does not attempt to provide comprehensive prevention, automated incident response, endpoint management, or enterprise-scale security orchestration.

These boundaries keep the project focused on its primary objective: demonstrating an end-to-end threat detection workflow from log ingestion to alert presentation.
